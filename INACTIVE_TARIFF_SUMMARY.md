# Сводка: Система неактивных тарифов

## ✅ Выполненная задача

Создана полная система автоматического перехода пользователей с тестового тарифа на неактивный тариф через 14 дней после регистрации.

## 📋 Что было сделано

### Backend

1. **Добавлен новый тип тарифа**
   - `TariffType.INACTIVE` в `database.py`
   - Тариф "Неактивный" с нулевым доступом

2. **Добавлено поле в модель User**
   - `test_period_end_date` (DateTime)
   - Автоматически устанавливается при регистрации (14 дней)

3. **Создан модуль управления тарифами**
   - `backend/tariff_manager.py`
   - `check_and_update_expired_test_tariff()` - автоматическая проверка
   - `get_test_period_days_remaining()` - подсчет дней

4. **Обновлен API endpoint**
   - `/api/v1/user/tariff` теперь автоматически проверяет истечение
   - Возвращает количество дней до конца тестового периода

5. **Обновлены схемы**
   - `UserTariffResponse` теперь включает:
     - `test_period_days_remaining`
     - `test_period_end_date`

6. **Обновлена инициализация**
   - `init_admin_data.py` создает неактивный тариф
   - `add_inactive_tariff.py` для существующих БД

7. **Миграция БД**
   - `ensure_database_compatibility()` добавляет `test_period_end_date`

### Frontend

1. **Обновлены типы TypeScript**
   - `UserTariffResponse` с новыми полями

2. **Обновлена логика календаря**
   - `calendar.tsx` обрабатывает неактивный тариф
   - Замыливает тренировки после даты истечения

3. **Обновлен профиль**
   - Отображение дней до конца тестового периода
   - Предупреждение для неактивного тарифа

## 🎯 Как это работает

### Регистрация нового пользователя

```
Пользователь регистрируется
    ↓
Назначается тестовый тариф
    ↓
test_period_end_date = now + 14 дней
```

### Автоматическая проверка

```
Пользователь открывает приложение
    ↓
GET /api/v1/user/tariff
    ↓
check_and_update_expired_test_tariff()
    ↓
Если now >= test_period_end_date:
    Переход на INACTIVE тариф
```

### Отображение в календаре

```
INACTIVE тариф:
├─ Доступны: тренировки до test_period_end_date
└─ Замылены: тренировки после test_period_end_date
```

## 📊 Правила доступа

| Тариф | Период доступа | Замыленные тренировки |
|-------|---------------|----------------------|
| **Test** | 14 дней от сегодня | После 14 дней |
| **Inactive** | До даты истечения | После даты истечения |
| **Trial** | 21 день от сегодня | После 21 дня |
| **Pro** | Весь план | Нет |

```sql

SET test_period_end_date = datetime('now', '-1 day')
WHERE email = 'test@example.com';
```

**Результат при следующем запросе:**
- Автоматический переход на "Неактивный" тариф
- Замыливание тренировок после даты истечения

## 📊 Workflow

```
День 0: Регистрация
└─→ Тариф: Тестовый
    test_period_end_date: +14 дней

День 1-13: Активный период
└─→ Отображается: "До конца: X дней"
    Доступны: тренировки на 14 дней вперед

День 14: Последний день
└─→ Отображается: "До конца: 0 дней"
    Доступны: тренировки только на сегодня

День 15+: Автоматический переход
└─→ Тариф: Неактивный
    Отображается: "Тестовый период истек"
    Доступны: только тренировки до дня 14
    Замылены: все после дня 14
```
