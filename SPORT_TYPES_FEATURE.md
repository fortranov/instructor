# Функционал выбора видов спорта для тарифов

## Описание

Реализована возможность настройки доступных видов спорта для каждого тарифа. Администратор может выбрать, какие виды спорта (бег, велосипед, плавание, триатлон) будут доступны пользователям с определенным тарифом при создании плана тренировок.

## Изменения в базе данных

### Таблица `tariffs`

Добавлены новые колонки:
- `allow_running` (INTEGER, DEFAULT 1) - Доступен ли бег
- `allow_cycling` (INTEGER, DEFAULT 0) - Доступен ли велосипед
- `allow_swimming` (INTEGER, DEFAULT 0) - Доступно ли плавание
- `allow_triathlon` (INTEGER, DEFAULT 0) - Доступен ли триатлон

### Значения по умолчанию

После миграции:
- **Тестовый тариф**: только бег
- **Пробный тариф**: только бег
- **Про тариф**: все виды спорта (бег, велосипед, плавание, триатлон)
- **Неактивный тариф**: только бег

## Backend изменения

### 1. Модель данных (`backend/database.py`)


Обновлены схемы:
- `TariffResponse` - добавлены поля для видов спорта
- `TariffUpdate` - добавлены поля для обновления видов спорта

### 3. API администрирования (`backend/api_admin.py`)

Обновлен endpoint `PUT /api/v1/admin/tariffs`:
- Теперь сохраняет настройки видов спорта для каждого тарифа

- Возвращает информацию о доступных видах спорта

### 4. API пользователей (`backend/api_routes.py`)

Обновлен endpoint `GET /api/v1/competition-types`:
- **Требует аутентификации**
- Фильтрует типы соревнований на основе тарифа текущего пользователя
- Возвращает только те виды спорта, которые доступны для тарифа пользователя

## Миграция базы данных

### Скрипт миграции

Файл: `backend/migrate_tariff_sports.py`

Что делает скрипт:
1. Добавляет новые колонки в таблицу `tariffs`
2. Устанавливает значения по умолчанию для существующих тарифов
3. Для тарифа "Про" включает все виды спорта
4. Для остальных тарифов оставляет только бег

### Запуск миграции

```bash
python backend/migrate_tariff_sports.py
```

## Использование

### Для администратора

1. Перейти в раздел "Администрирование" → "Тарифы"
2. В таблице "Доступные виды спорта" отметить нужные виды спорта для каждого тарифа
3. Нажать "Сохранить настройки"

### Для пользователя

При создании плана тренировок в профиле:
1. В выпадающем списке "Тип соревнования" будут отображаться только те виды спорта, которые доступны для тарифа пользователя
2. Если у пользователя тариф "Тестовый" (только бег), он увидит только беговые дистанции
3. Если у пользователя тариф "Про" (все виды спорта), он увидит все доступные варианты

## Примеры сценариев

### Сценарий 1: Ограничение бесплатного тарифа

Администратор хочет, чтобы пользователи с бесплатным тестовым тарифом могли создавать планы только для бега:

1. В разделе "Тарифы" снять все галочки для тестового тарифа, кроме "Бег"
2. Сохранить настройки
3. Пользователи с тестовым тарифом смогут создавать планы только для беговых дистанций

### Сценарий 2: Расширение функционала для платных пользователей

Администратор хочет дать пользователям с тарифом "Про" доступ ко всем видам спорта:

1. В разделе "Тарифы" отметить все галочки для тарифа "Про"
2. Сохранить настройки
3. Пользователи с тарифом "Про" смогут создавать планы для бега, велосипеда, плавания и триатлона

### Сценарий 3: Специализированный тариф

Администратор хочет создать специализированный тариф для триатлетов:

1. Настроить тариф "Пробный" с доступом к бегу, велосипеду, плаванию и триатлону
2. Сохранить настройки
3. Пользователи с пробным тарифом смогут создавать комплексные планы для триатлона

## Технические детали

### Логика фильтрации

1. При запросе типов соревнований (`GET /api/v1/competition-types`), сервер:
   - Проверяет тариф текущего пользователя
   - Читает настройки доступных видов спорта для этого тарифа
   - Возвращает только те категории, которые разрешены

2. Frontend:
   - Получает уже отфильтрованный список
   - Отображает только доступные виды спорта в выпадающем списке
   - Не требует дополнительной логики фильтрации

### Безопасность

- Настройки тарифов может изменять только администратор
- Endpoint `/api/v1/competition-types` требует аутентификации
- Фильтрация происходит на стороне сервера, что исключает обход ограничений

## Будущие улучшения

Возможные направления развития функционала:

1. **Гибкие настройки дистанций**: возможность настраивать конкретные дистанции для каждого тарифа (например, только 10 км и полумарафон, но не марафон)

2. **Временные акции**: возможность временно разблокировать виды спорта для определенных тарифов

3. **Персональные настройки**: возможность индивидуально настраивать доступные виды спорта для конкретных пользователей

4. **Аналитика**: отслеживание популярности различных видов спорта среди пользователей

5. **Уведомления**: информирование пользователей о доступных дополнительных видах спорта при переходе на более высокий тариф
